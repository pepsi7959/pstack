### Worktree and simulator cleanup

1. Snapshot and audit. Record `df -h /`, then run `scripts/worktree-audit.sh [-b <pr-base-ref>] [repo-path]` (principle-build-the-lever). Without `-b` it checks `MERGED` against `origin/HEAD`, so pass `-b origin/<branch>` when PRs target another branch. It reads paths from `git worktree list`, never hand-typed, since a hand-typed `myrepo-worktrees/x` misses one that lives at `~/worktrees/myrepo/x` (principle-encode-lessons-in-structure). It classifies each worktree by size, age, merge state, work that removal would lose, PR state, and the newest chat that touched it, then suggests a bucket. Anything it could not read makes the bucket `review`. The transcript scan is slow, so background it.
2. The bucket is advice, not permission. The pinned and active chats are the real artifact (principle-prove-it-works). Get that set from the user and from `opencode session list`, and cross-check every candidate. The lever has marked `safe` a worktree the user had pinned, so the pinned set wins.
3. Verify usage before deleting. For every `verify-recent-chat` row, or anything you doubt, fan subagents out to read the transcripts and report whether the chat is pinned or ongoing and which worktrees it touches (principle-guard-the-context-window, transcripts are bulk). A pinned chat spawns arena and repro trees into sibling worktrees via background subagents, and those are in use even when their names never show in the session list. Pick each subagent's agent by role, per the Subagents section.
4. Pause on irreversible loss. `wip:N` is N tracked uncommitted edits, `untracked:N` is N files git has never seen, and `ignored:N` is N ignored paths that nothing rebuilds, such as `.env`. `reflog:N` is N commits that only this worktree's HEAD reflog reaches, so keep any with `git branch <name> <sha>`. `hold-locked` means another tool locked the tree. All of these are lost with the directory, so list them, name ignored files without printing their contents, and get a decision first. `review` means unproven, including any worktree with submodules. Per Autonomy, only `safe` and not in use proceeds. One `review` or `verify-recent-chat` row proceeds too: a detached worktree this run created, whose agent has finished, when step 3 finds no chat other than this run's touching it, DIRTY is `clean`, the audit printed no `warn:` line, the tree has no `.gitmodules`, and after `git fetch` `git branch -r --contains <its HEAD>` names a branch. Everything else pauses, and your own proof that nothing would be lost does not replace these checks. With nobody to ask, keep it.
5. Prune the confirmed set. Per path, `git worktree remove <path>`. Git then refuses modified or untracked files, but it deletes ignored files without asking, so the audit is their only gate. Add `--force` only for a path the user approved. If the directory survives, `rm -rf` it only when `git worktree list` no longer names it, never to get around a lock. Commits on a branch survive. Commits only the worktree's reflog reached do not. Confirm with `df -h /` and re-list.
6. Simulators and other reclaimers. Simulators are usually the next-biggest win. `xcrun simctl --set testing delete all` (XCTestDevices clones), `xcrun simctl delete unavailable`, and `xcrun simctl runtime list` then `runtime delete <id>` for old runtimes. More when needed: Xcode `DerivedData` and `iOS DeviceSupport`, package caches (pnpm, uv, brew, yarn). Clear only caches the user has not said to keep.

This is the one playbook that deletes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** `df -h /` before and after with space reclaimed, the worktrees pruned, and a one-line reason for each held back (in-use by which chat, or uncommitted work).
